# 企业知识库（@mindlink-ai/dsh-company-knowledge）

一句话：把公司放在本地或 NAS 上的 Markdown 知识库接入 DSH，让同事和 Agent 干活时都能读到「企业记忆」。

## 1. 它解决什么问题

公司信息散在十几个共享盘文件夹里：产品价格、SLA、售前材料、常见问题，每次都要翻半天。装好这个插件后：

- 同事可以直接问 DSH「我们专业版多少钱」，不用再翻目录；
- 回答基于知识库原文，并给出文档路径，便于核对；
- 知识库内容更新后，点一下「重新索引」即可，不需要动插件。

## 2. 工作原理

1. 扫描：读取配置目录下的所有 `.md` 文件，解析 front matter 与正文。
2. 建索引：在本机生成索引缓存 `~/.dsh/company-kb/index.json`（Windows 为 `%USERPROFILE%\.dsh\company-kb\index.json`）。
3. 注册工具：为 Agent 注册 4 个知识库工具。
4. 注入概览：每轮对话开始时自动注入一段知识库概览（可在设置中关闭）。

| 工具 | 用途 |
| --- | --- |
| `kb_status` | 查看知识库路径、文档数、最近索引时间与错误信息 |
| `kb_search` | 按关键词检索，返回相关文档与匹配片段 |
| `kb_read` | 读取指定文档的全文 |
| `kb_list` | 列出全部文档的标题、分类与路径 |

边界说明：插件默认只读；唯一的写路径是用户在面板里点「保存」——只允许知识库目录内的 `.md`，写入前校验路径与 mtime 冲突（别人改过就报 409，不覆盖），保存后自动重索引该篇。索引只存在本机。

## 3. 安装（局域网分发）

1. 把整个 `company-kb-plugin` 目录放到共享盘，例如 `\\NAS\软件\DSH插件\company-kb-plugin`；
2. 打开 DSH 的 Plugin Manager，安装本地插件目录（install_bundle），目标填该目录的绝对路径（例：`\\NAS\软件\DSH插件\company-kb-plugin`）；
3. 重启 DSH 或刷新页面后生效。

安装完成后，profile 下的 `package.json` 与 `cordis.patch.yml` 由 Plugin Manager 维护，不要手改。共享盘需要给同事读取权限。

目录里带一个 `vendor/toastui/`（富文本编辑器，约 730 KB，MIT），随插件一起分发；Host 通过 `/company-kb/vendor/*` 同源提供，不需要额外装 npm 包，也不访问外网。

## 4. 配置知识库路径

两个入口打开的是同一个「企业知识库」面板：

- **左侧菜单栏图标**（全局面板，和「定时任务」「微信 bot」并排）——日常查看状态用；
- **设置 → 企业知识库**（设置分区，order 25）——排查配置时用。

操作步骤：

| 步骤 | 操作 |
| --- | --- |
| 1 | 在「知识库位置」粘贴 UNC 路径（如 `\\NAS\共享\知识库`）或映射盘符（如 `Z:\知识库`） |
| 2 | 点击「保存并重建索引」 |
| 3 | 到「索引状态」确认文档数大于 0 |

- 设置保存在本机 `%USERPROFILE%\.dsh\company-kb\settings.json`；
- 也支持用环境变量 `DSH_COMPANY_KB_PATH` 提供默认路径（设置页未配置时作为默认值）；
- 推荐使用 UNC 路径：映射盘符在用户登录前不可用，可能导致路径不可用；
- 日常内容更新后点「重新索引」即可。

### 4.1 按目录树浏览与编辑

面板左半区是文件目录树（按知识库真实目录结构），右半区默认是**富文本编辑器（Toast UI Editor，MIT）**：打开就是排版好的文档，直接像文档软件一样改，顶部工具栏可加粗、标题、列表、表格、代码块，保存后写回 Markdown。

| 操作 | 效果 |
| --- | --- |
| 点目录行 | 展开 / 收起该目录；数字是目录内文档数 |
| 点文档行 | 右侧以富文本方式打开（所见即所得） |
| `富文本 / 源码` | 默认「富文本」（所见即所得）；「源码」是整篇 Markdown textarea，用于批量改或兜底 |
| 「文档属性 ▸」 | 展开编辑 YAML front matter（标题/摘要/分类/标签/更新）；富文本只编辑正文，保存时原样拼回 |
| 点「保存」或 `Ctrl+S` | 写回原文件，自动重索引这一篇，AI 立刻能检索到新内容 |
| 点「还原」 | 放弃未保存修改，重新从磁盘读取 |
| 目录树顶部输入框 | 按标题 / 路径 / 摘要筛选文档 |
| 右键目录行 | 菜单：`新建文档` / `新建文件夹` / `重命名` / `删除`（根目录只有前两项） |
| 右键文档行 | 菜单：`打开` / `重命名` / `删除`；右键空白处等同于右键根目录 |
| 重命名 / 删除 | 在树内弹出内联表单，`Enter` 确认、`Esc` 取消；删除需二次确认，非空文件夹再确认递归删除 |
| 「知识库路径」按钮 | 展开路径设置（未配置时默认展开） |

说明：

- 富文本编辑器是**第三方成熟库** Toast UI Editor 3.2.3（MIT），随插件放在 `vendor/toastui/`，由 Host 同源路由 `/company-kb/vendor/*` 提供，不依赖 CDN、内网离线可用；构建方式见 `vendor/toastui/NOTICE.md`；
- 富文本模式只编辑正文；front matter 单独编辑，保存时拼回 `---` 块，保证知识库字段不丢；
- 官方库的 Markdown 输出会做常规规范化（例如表格对齐、列表符号），语义不变；需要逐字控制时切「源码」模式；
- 如果浏览器加载不到富文本库（文件缺失 / CSP 限制），面板会提示「富文本编辑器不可用」，并引导切到「源码」继续编辑。

写入安全约束：

- 只允许知识库根目录内的 `.md` / `.markdown`，`..`、绝对路径、软链接逃逸都会被拒绝；
- 新建 / 重命名会校验名称：拒绝 `.` 开头、Windows 非法字符、保留名（CON/PRN 等）、超长名称；新建文档自动补 `.md` 并写入 front matter 模板；
- 删除文件直接确认；文件夹非空时返回 `NOT_EMPTY`，需再次确认才递归删除；
- 保存时带上打开时的 mtime：文件被别人改过返回 `409 CONFLICT`，不覆盖，提示重新打开；
- 原子写入（临时文件 + rename），网络盘不支持覆盖 rename 时退回直接写入；
- 单文件超过 `maxFileBytes`（默认 400 KB）不允许在线编辑，避免误伤大文件；
- 新建 / 重命名 / 删除后会全量重建索引，状态里立刻能看到新目录结构。

## 5. 知识库目录与编写规范

建议按编号分目录：`00-公司/`、`10-产品/`、`20-流程/`、`30-常见问题/`。文件名即文档 id，用中文名，如 `星链助手-功能说明.md`。

每个文件第 1 行必须是 `---`，front matter 字段如下：

| 字段 | 说明 |
| --- | --- |
| `title` | 文档标题，用于概览与检索结果 |
| `summary` | 一句话摘要，不超过 60 字，会出现在自动注入的概览里 |
| `category` | 分类，如 公司、产品、流程、常见问题 |
| `tags` | 关键词，英文逗号分隔 |
| `updated` | 更新日期，格式如 2026-11-09 |

`title` 与 `summary` 会出现在自动注入的概览中，summary 写清楚能显著提升命中率。文件必须用 UTF-8 保存。配套的 `company-kb-demo/` 目录是一份可直接使用的示例知识库。

## 6. Agent 怎么用

直接提问即可，例如：

- 「我们专业版多少钱？」
- 「星链助手支持哪些平台？」
- 「客户要求私有化部署，怎么回复？」
- 「客户报 P1 故障，多久要响应？」
- 「售前报价需要客户提供哪些材料？」

Agent 的处理方式是先调用 `kb_search` 定位相关文档，需要细节时再用 `kb_read` 读全文，回答里会引用文档路径（如 `10-产品/星链助手-功能说明.md`）。

## 7. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 状态显示「路径不可用」 | 盘符未映射、NAS 无访问权限、UNC 路径拼写错误；推荐直接用 UNC |
| 文档数不更新 | 点「重新索引」；NAS 较慢时需等待扫描完成；单个知识库超过 2000 个 `.md` 时，超出部分不参与索引 |
| Agent 没有被注入概览 | 未配置路径、索引文档数为 0、或概览注入（injectPrompt）被关闭 |
| 内容乱码 | 文档必须是 UTF-8 编码，另存为 UTF-8 后重新索引 |
| 面板打开显示 404 /「读取状态失败」 | Host 的 `/company-kb/*` 路由尚未注册（冷启动时序）。插件已在启动后自动补注册（最多等 60 秒），稍等或刷新页面即可；若仍出现，在对话里让 Agent 调 `kb_status`，把 `webRoutes` / `webError` 字段反馈给维护者 |

## 8. 更新与升级

- 插件升级：替换 `company-kb-plugin` 目录后，在 Plugin Manager 重新安装，重启或刷新后生效；
- 知识库更新：不需要重装插件，点「重新索引」即可。

## 9. 安全与合规

- 知识库只收录可公开的信息：企业基础信息、产品资料、流程与常见问题；
- 不要把客户隐私、密钥、合同原文等敏感内容放进去；
- 插件默认只读；写操作只有用户主动保存，且限定在知识库目录内的 `.md`，不删除、不重命名、不上传；
- 保存前校验路径越界与 mtime 冲突，避免覆盖别人的修改；
- 索引与设置只保存在本机。

## 10. 知识库编辑规则与方式

知识库目录对 Agent 是**可直接编辑**的普通目录，对插件则是**只在用户保存时写入**。两条路径的规则一致：

| 步骤 | 动作 |
| --- | --- |
| 1 | 说明改哪个文件、改什么（新增 / 修改 / 删除 / 重命名） |
| 2 | **向用户申请许可**：DSH 对网络路径（`U:` 等映射盘）的写入会弹窗授权，未确认不得写入 |
| 3 | 写入目标文件（UTF-8 无 BOM，front matter 齐全） |
| 4 | 刷新索引：面板保存会自动重索引本篇；其他改动点「重新索引」或 `POST /company-kb/reindex` |
| 5 | 调用 `kb_status` 复核 `docs` 与 `errors`，向用户回报结果 |

规则：

- **不保留本地副本**：不在工作区另存知识库快照，改完即止；
- **不编造**：官网未披露的信息标 `【待确认】`，价格、SLA、资质、客户名单不得推测填写；
- **删除前确认已替换**；需要回滚时，备份放在知识库目录**之外**（目录内的 `.md` 会被索引进知识库）；
- 新增文档必须按第 5 节的 front matter 与命名规范写，`summary` ≤ 60 字。

> 这段规则同时写在插件的注入提示词里（`index.js` 的 `buildOverviewText`），每个新会话开头都会看到，因此 Agent 无需额外提醒就会按此执行。

### 10.1 HTTP 接口（面板使用，同源）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/company-kb/status` | 状态、索引统计与文档清单（含 `relPath`、`mtime`） |
| GET | `/company-kb/doc?path=<relPath>` | 读取单篇原文（编辑器打开） |
| POST | `/company-kb/doc/save` | 保存单篇：`{ path, text, baseMtime }`；mtime 过期返回 409 `CONFLICT` |
| POST | `/company-kb/settings` | 保存知识库路径并重建索引 |
| POST | `/company-kb/reindex` | 全量重建索引 |
| POST | `/company-kb/fs` | 新建 / 重命名 / 删除：`{ action: 'mkdir'\|'create-doc'\|'rename'\|'delete', dir?, name?, path?, newName?, recursive? }` |
| GET | `/company-kb/vendor/<file>` | 托管 `vendor/` 下的编辑器静态资源（js/css，带 ETag 缓存） |

POST 带同源校验（跨域 `Origin` 直接 403）；保存接口请求体上限 6 MB。`vendor/` 路由只允许知识库插件目录内的 js/css/svg/png/woff2/json，拒绝路径越界。
