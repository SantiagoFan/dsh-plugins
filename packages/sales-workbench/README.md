# 市场线索（Market leads）

DSH 左侧边栏插件：按「采集主题 + 采集渠道 + 地区范围」每天定时抓取公开公告/页面，识别成**意向客户线索**，可浏览、复制、导出 Excel，也能让 AI 直接读取。

线索字段（面板与导出统一）：

| 字段 | 说明 |
| --- | --- |
| 公司名称 | 优先取「采购人 / 招标人 / 采购单位 / 建设单位：」这类标注，其次标题里的公司全称 |
| 联系人 | 「联系人：王工」这类写法，2-6 个汉字，可带先生/女士/经理/工 |
| 联系电话 | 手机（11 位）、400/800 热线、带区号座机；靠近「电话/联系方式」字样的优先，手机优先于座机 |
| 地区 | 「项目地点 / 地址 / 服务地点：」标注，其次省份，再其次「XX市（XX区）」；识别不出用渠道的「默认地区」 |
| 备注（网址来源） | 原文里与联系方式相关的片段 + 来源链接（点击直达原文） |
| 采集时间 | 这条线索是什么时候被抓到的，便于和日报/跟进记录对齐 |

- **面板入口**：左侧边栏的漏斗图标「数据采集器」，五个页签：总览 / 采集主题 / 采集渠道 / 定时任务 / 意向客户。
- **默认行为**：每天 **07:30（北京时间）** 自动采集一次。Harness 关闭时不会采集；重新打开后如果错过了当天的时间点，会在启动约 20 秒后补采一次。
- **数据位置**：`~/.dsh/data-collector/`
  - `state.json`：主题、渠道、定时、线索与运行记录（目录 0700、文件 0600）
  - `reports/YYYY-MM-DD.md`：当天的线索表格，每次采集后重写
  - 可用环境变量 `DSH_DATA_COLLECTOR_DIR` 换目录。

## 三个配置各管什么

| 配置 | 位置 | 作用 |
| --- | --- | --- |
| 采集范围（地区） | 「采集主题」页签顶部 | **默认只收内蒙古自治区的线索**。内蒙古会自动展开成 12 盟市与主要旗县（呼和浩特、包头、鄂尔多斯、锡林郭勒…），所以页面里只写「呼和浩特市」也能命中；可改成任意省/市，清空=不限地区。地区识别不出来时按「智能判断 / 保留 / 丢弃」处理：智能判断（默认）会看公司名或标题里有没有范围内城市，避免把「郴州华润燃气」这类外地线索放进来。 |
| 采集主题 | 「采集主题」页签 | 业务关键词（采购、招标、演练、消防…，顿号/逗号/换行分隔）。标题或摘要命中任一关键词的页面才进入线索识别。可只关注部分渠道；不勾 = 全部渠道。 |
| 采集渠道 | 「采集渠道」页签 | 从哪里采：RSS / Atom、JSON 接口、网页列表、网页搜索。每个渠道可单独启用、限制页数，并配「是否抓详情页」「每个渠道最多抓几个详情页」「默认地区」。 |
| 定时任务 | 「定时任务」页签 | 每天几点、时区、是否启用、是否启动补采、线索保留天数、单次采集上限。 |

采集时每个启用的渠道只抓一次列表，再按主题关键词分派；命中主题的页面里如果缺公司/联系人/电话，会按渠道配置跟进详情页正文补全（每次运行最多 30 个详情页，每渠道最多 20 个，单页 10 秒超时）。去重按**电话**，没有电话按**公司名**，再没有按**网址**——同一个号码不会重复入库。

一条页面要成为「线索」，至少要满足一个：识别出公司名称、电话或联系人，或者标题像采购/招标公告（含采购、招标、中标、询价、磋商、比选、竞价、遴选、征集、招商、合作、维保等词）。三者都没有、标题也不像公告的页面直接跳过，记为「无联系方式跳过」，避免把普通资讯塞进客户列表。

线索还要通过**地区范围**（默认内蒙古）：地区识别不出来时按「地区识别不出来时也保留」处理，被范围挡掉的记为「地区外跳过」。

「线索」页签里，日期/主题/关键词/有无电话筛选同时作用于列表与导出：

- **线索状态页签**：全部 / 今日采集 / 未同步 / 已同步 / 写入失败 / 无手机号（带条数），一键切换；接口参数 `sync=unsynced|synced|failed|no_phone|today`，导出也跟随该筛选。今日采集按配置时区判断「今天」，与定时任务口径一致。

- **导出 Excel（.xlsx）**：真正的 Excel 文件（不是 CSV），9 列：`公司名称 / 联系人 / 联系电话 / 地区 / 备注 / 来源网址 / 采集时间 / 主题 / 渠道`；表头加粗、冻结首行、带自动筛选，中文不乱码，可直接导入 CRM 或继续加工。
- **复制本页**：制表符分隔，直接粘到 Excel。
- **只看有电话**：只留带电话的线索，外呼前先筛一遍。
- **逐行写入 CRM**：每行「操作」里有「写入 CRM」，单条也会先做手机号/公司名查重，通过才写入并移入线索池；被拦下时弹窗说明原因。已同步的行不再显示按钮。
- **批量写入 CRM**：勾选多行后点顶部「写入 CRM」，预检弹窗确认后逐条写入（只写有手机号、未同步的行）。
- **逐行详情**：表格默认只显示 公司名称 / 联系人 / 联系电话 / 地区 / 采集时间，备注与来源网址收在「详情」弹窗里（点行尾「详情」打开，可一键复制整条线索）。
- **逐行删除**：表格「操作 → 删除」，点一次进入确认态、再点一次才真删（只删这一条；同一条线索以后再次被抓到时会重新入库，因为去重记录随线索一起删掉了）。
- **清空线索**：只清线索与去重记录，主题和渠道配置保留；删除主题会连带删掉它已采集的线索。

## 存储：SQLite（v3）

线索和运行记录存在本机 SQLite 数据库里，配置仍是 JSON：

```
~/.dsh/data-collector/
├─ state.json     配置：主题 / 渠道 / 地区范围 / 定时任务（人类可读，可手改）
├─ leads.db       线索 + 运行记录（SQLite，Node 内置 node:sqlite，无第三方依赖）
└─ reports\       每天一份 Markdown 线索表
```

`leads.db` 的表与索引：

| 表 | 内容 | 关键索引 |
| --- | --- | --- |
| `leads` | 公司、联系人、电话、`phone_digits`、地区、备注、标题、来源网址、采集时间、主题/渠道 | `key` 唯一索引（去重）、`date`、`fetched_at`、`phone_digits`、`topic_id`、`channel_id` |
| `runs` | 每次采集的统计与各渠道明细 | `started_at` |

- **去重**：`key` = 电话 → 公司名 → 网址，插入用 `INSERT OR IGNORE`，重复的自动跳过并计入「已存在跳过」。去重窗口 = 「保留天数」（默认 30 天），超期线索被裁剪后同一电话才可能再次入库。
- **分页**：`LIMIT/OFFSET` 服务端分页，面板可选每页 20/50/100 条，翻页不重新拉全表。
- **检索**：公司/联系人/电话/地区/备注/标题/来源 全文 `LIKE` 检索，可叠加日期、日期区间、主题、渠道、「只看有电话」筛选。
- **导出**：Excel（xlsx）导出跟随当前筛选（导出全量，不受分页限制，上限 2 万条）。CSV / Markdown 导出已移除。
- **迁移**：从旧版（线索存 JSON）升级时，首次启动会把手里的 `items/runs` 导入 `leads.db`，然后从 `state.json` 移除，不会丢数据。
- **依赖**：`node:sqlite` 需要 Node ≥ 22.5（DSH 桌面端运行时是 Node 24，直接可用；如果你用系统自带 Node 20 跑测试会报 `No such built-in module: node:sqlite`，需要用 DSH 的运行时跑，见下方测试说明）。

## 采集范围（地区）

在「采集主题」页签顶部配置，可逐个添加城市标签（呼和浩特市、包头市…），也可以只加「内蒙古」自动覆盖全省 79 个城市/旗县关键词。地区识别不出来时按「智能判断 / 保留 / 丢弃」处理。

## 渠道类型与填写要点

- **RSS / Atom**：填 feed 地址（不是文章页）。
- **JSON 接口**：填接口地址；可选「数组路径」（如 `data.list`）与字段名。
- **网页列表**：填列表页地址；建议填「链接过滤」正则（如 `/tzgg/` 或 `t\d{8}_\d+`），否则导航链接也会被当成页面。
- **网页搜索**：填搜索词（留空则用主题关键词），走 Host 的 `ctx.web.search`。

判断一个渠道好不好用，最快的方式是保存后点「测试渠道」：它会抓一次并显示识别出的前几条线索（公司/联系人/电话/地区 + 来源），以及「几条有电话」。

### JSON 渠道的两项扩展（v3.2）

接口类渠道现在支持：

- **名录字段直映射**：`fieldCompany / fieldContact / fieldPhone / fieldRegion` 分别对应接口里的公司、联系人、电话、地区字段。填了公司字段就按「机构名录」处理——不按主题关键词筛选（整份名录都要），只按地区范围筛。
- **链接模板**：列表接口只给 ID 时，用 `linkTemplate` 拼详情地址，例如 `https://ggzyjy.nmg.gov.cn/jyxx/index_39.html?id={sourceDataKey}`。
- **URL 查询词**：URL 里可写 `{query}`，会替换成渠道的查询词（例如 `...?noticeName={query}`）。

### 内置 CRM（原 Cordys CRM 插件已并入）

CRM 客户端与配置已内置到本插件，**不再需要启用独立的「Cordys CRM」插件**。左侧面板新增「CRM」页签：

- **连接配置**：服务器地址、Access Key、Secret Key、可选组织 ID；「保存并测试连接」会立即验证连通与鉴权，并显示当前登录账号；
- **只读开关**：默认只读（拒绝写入），确认无误后取消勾选才允许真正创建线索；
- **写入默认值**：默认线索池与意向产品，写入时使用；
- **配置位置**：`~/.dsh/data-collector/crm.json`（0600）；第一次打开会自动**迁移**旧插件 `~/.dsh/cordys-crm/config.json` 的地址与 Key，无需重新输入；
- 接口：`GET /crm/status`、`POST /crm/connect`、`POST /crm/test`、`GET /crm/options`、`POST /crm/precheck`、`POST /crm/push`、`POST /crm/config`；
- 工具动作：`crm_status / crm_connect / crm_search / crm_options / crm_precheck / crm_push / set_crm`。

「线索」页勾选若干条 → 「写入 CRM」→ 预检 → 确认写入。规则（2026-11-23 定稿）：

- **只写线索**，不写客户；创建后移入指定线索池（默认「EvSim线索公海」）。
- **只允许手机号非空的线索**；没电话的行勾选框置灰，预检也会再拦一次。
- **写入前两次查重**：手机号在 CRM 全局搜索一次、公司名称再搜一次，**任一命中即拒绝**（线索/联系人/客户/商机都算命中，线索池单独按池查）。命中的线索会自动在本地标记「已同步」并记录命中的 CRM 记录 id，之后不再出现在可勾选/可写入范围，避免重复操作。
- **写入字段**：公司名称、联系人名称、联系人电话、地区（`LOCATION`，值形如 `1501-`，按盟市编码）、备注（来源渠道·主题｜采集时间｜地区｜来源 URL）、线索来源（其他）。意向产品非必填。
- 写入成功的线索本地标记「已同步」（`crm_id / sync_state / synced_at` 三列），再点不会重复查、重复写。
- **写入结果有明确反馈**：完成后弹出「CRM 写入结果」窗口（成功/失败条数 + 每条原因，失败可重试），同时右下角出现浮动提示（成功绿色、失败红色，6 秒自动消失，也可手动关闭）；单条写入同样有浮动提示。

### 服务商线索（主要客户）

做数字化应急演练系统，买系统的是**提供演练服务的公司和技术咨询机构**，所以除了采购公告，还专门采集服务商：

- **中标公告里的「中标供应商」**：这类公司正是演练服务的承接方。识别到 `中标供应商/成交供应商/供应商名称` 等标注时，线索主体直接取供应商（而不是采购人），备注自动标成「中标服务商」；普通招标公告仍按采购方处理。
- **公司官网 / 行业协会名录 / 工商信息页**：搜索「应急演练服务 公司」「消防技术服务机构」「消防培训 机构」等词，抓公司名 + 电话 + 地址。
- 平台自带的客服号（如天眼查 `400-608-0000`）、网站服务热线、举报电话都会被排除，不会混进线索。

**为什么很多平台只能靠搜索覆盖**：内蒙古自治区公共资源交易网（`ggzyjy.nmg.gov.cn`）、内蒙古政府采购网（`ccgp-neimenggu.gov.cn`）以及呼和浩特 / 包头 / 鄂尔多斯的公共资源交易网站，列表页基本是 JS 动态渲染或加密接口，直接抓 HTML 拿不到公告；搜索引擎索引里反而有这些公告，所以用定向搜索词覆盖。若以后这些站点开放静态列表，把 URL + 链接正则在面板里配一个网页列表渠道即可。

另外已实测不可用：包头市应急管理局、鄂尔多斯公共资源交易、呼和浩特市应急管理局（站点无法访问或反爬）。

## 与 AI 配合

插件注册了 Agent 工具 `data_collector`：

| action | 用途 |
| --- | --- |
| `status` / `list` | 配置摘要、上次运行、下次运行时间 |
| `results` | 查线索（分页 `page/pageSize`、检索 `q`、筛选 `date/dateFrom/dateTo/topic/channel/hasPhone`、排序 `sort`） |
| `delete_lead` | 删除单条线索（传 `id`） |
| `save_topic` / `delete_topic` | 新建、更新、删除采集主题 |
| `save_channel` / `delete_channel` | 新建、更新、删除采集渠道（含 `followDetail`、`detailLimit`、`region`） |
| `set_schedule` | 改定时（时间、开关、时区、保留天数、单次上限） |
| `set_scope` | 改采集范围（地区），例如 `regions: ["内蒙古"]`；空数组=不限地区 |
| `test_channel` | 抓一次，看能识别出几条线索 |
| `run` | 立刻采集一次（默认等结束，最多 90 秒） |
| `clear_results` | 清空已采线索与去重记录（配置保留） |

可以直接说：「把今天识别到的带电话的线索列出来」「加一个主题：消防维保，关键词 消防、维保、采购」「现在跑一次」。插件同时注入系统提示，要求汇报线索时保留来源网址、不要把识别结果当成已核实事实。

## 限制与注意

- 线索字段是**启发式识别**：中文公告写法千差万别，可能把代理机构当客户、把传真当电话、把公司名截断。对外联系前请点来源链接核对原文。
- 采集对象是公开页面/接口，**不含登录态**；需要登录或强反爬的站点会失败，面板会显示失败原因。
- 部分站点把电话做成图片、或在详情页才展示；前者识别不到，后者靠「抓详情页」。
- 只在 Harness 运行时采集；它不注册系统计划任务，也不会在应用关闭时唤醒。
- 采集到的联系人姓名与电话来自公开网页，请按当地法律法规与平台条款使用（营销外呼的合规责任在使用方）。
- 单次每个渠道最多 200 个页面、整次采集默认最多 200 条线索（可调 10-1000），线索默认保留 30 天。

## 视觉与配色

面板只用 DSH 主题 token（`--dsw-alias-*`），暗色主题自动适配；彩色底纹由主题色 `color-mix` 派生，不写死色值：

| 语义 | 用色 | 出现位置 |
| --- | --- | --- |
| 品牌蓝 | `--dsw-alias-brand-primary` | 主按钮、当前页签、电话、选中列表项、进度条 |
| 绿 | `--dsw-alias-state-success-primary` | 已同步、成功提示、渠道启用 |
| 琥珀 | `--dsw-alias-state-warn-primary` | 未同步、无手机号、待处理 |
| 红 | `--dsw-alias-state-error-primary` | 写入失败、删除、只读/危险操作 |
| 灰 | `--dsw-alias-state-idle-primary` | 中性状态、未接入、禁用 |

标题前有品牌渐变竖条，页签选中项带同色底纹，状态页签按语义分色，统计卡左侧色条区分指标，侧边栏图标为渐变圆角块。

## 开发与测试

```sh
# 需要 DSH 运行时自带的 Node（≥22.5，含 node:sqlite）；系统 Node 20 会报 No such built-in module
ELECTRON_RUN_AS_NODE=1 "<DSH_NODE_EXECUTABLE>" test/leads.mjs
ELECTRON_RUN_AS_NODE=1 "<DSH_NODE_EXECUTABLE>" test/db.mjs
ELECTRON_RUN_AS_NODE=1 "<DSH_NODE_EXECUTABLE>" test/host.mjs
ELECTRON_RUN_AS_NODE=1 "<DSH_NODE_EXECUTABLE>" test/client-render.mjs
node test/time.mjs          # 时区与每日定时计算，不依赖 node:sqlite
node test/xlsx.mjs          # xlsx 生成（ZIP/转义/冻结行），纯 Node 内置模块
```

Windows PowerShell 里可以这样跑（`DSH_NODE_EXECUTABLE` 指向 `DeepSeek Harness.exe`）：

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
& $env:DSH_NODE_EXECUTABLE "$PWD\test\host.mjs"
```

`test/db.mjs` 直接测 SQLite 存储层（唯一索引去重、分页边界、LIKE 转义、筛选、导出、裁剪、旧数据 phone_digits 修复）；`test/host.mjs` 用假 ctx + 本地 HTTP 源站，覆盖配置 → 采集 → 详情页 → SQLite 去重 → 分页/检索/筛选 → 导出全链路；`test/client-render.mjs` 用假 React 渲染真实组件树，覆盖分页控件与表格。不依赖第三方包，也不需要浏览器。面板只通过同源 `/data-collector/*` 路由与 Host 通信，样式只用 `--dsw-alias-*` 主题 token。

## 从 v1 升级

v1 采的是「网页条目」，v2 改成「意向客户线索」。升级后状态文件里旧条目与去重记录会被丢弃，主题/渠道/定时配置与运行记录保留；下一次采集会按新模型重新生成线索。

## 卸载

在「插件」里关掉或移除本插件即可。数据保留在 `~/.dsh/data-collector/`，需要时手动删除。
